# 回调函数（Callback）学习笔记

> 本笔记整理自本次关于“回调函数”的讨论。
>
> **当前范围：只整理回调函数及其相关概念。**
> 函数指针、指针函数等容易混淆的内容暂不展开，后续单独讨论。

---

## 1. 什么是回调函数？

### 核心定义

**回调函数（Callback Function）**：

> 把一个函数/可调用对象作为参数交给另一个函数或组件，由后者在合适的时间调用它。

核心不是某一种语法，而是一种**编程思想和调用机制**。

可以理解成：

```text
调用者
  │
  │ 把“以后要执行的行为”交给另一个函数
  ▼
被调用函数
  │
  │ 在合适的时候调用
  ▼
回调
```

### 一句话记忆

> **回调 = 把“以后做什么”交给别人决定。**

---

## 2. 回调解决什么问题？

普通写法可能把调用关系写死：

```cpp
void process() {
    login();
    save();
    send_email();
}
```

此时 `process()` 明确依赖 `login()`、`save()` 和 `send_email()`。

如果以后想改成短信：

```cpp
send_sms();
```

就需要修改 `process()`。

这会产生较强的耦合。

---

## 3. 使用回调实现解耦

可以把“处理完成后做什么”交给外部：

```cpp
void process(std::function<void()> callback) {
    // 做自己的事情

    callback();
}
```

调用时决定具体行为：

```cpp
process(send_email);
```

或者：

```cpp
process(send_sms);
```

此时：

```text
              ┌── send_email
              │
process ─ callback
              │
              └── send_sms
```

`process()` 不需要知道具体调用的是谁。

它只需要知道：

> “你给我的东西符合要求，并且我可以在需要的时候调用它。”

因此，回调经常用于：

- 解耦
- 事件驱动
- 异步编程
- 网络编程
- GUI
- 线程池
- 定时器
- STL 算法
- 各种框架和库的扩展点

---

# 4. 回调和函数嵌套不是一回事

例如 Python：

```python
def process():
    def hello():
        print("hello")

    hello()
```

这里 `hello()` 是 `process()` 内部定义并直接调用的局部函数。

重点是：

> **函数嵌套强调“定义位置/作用域”。**

而回调：

```python
def process(callback):
    callback()

process(hello)
```

重点是：

> **把一个行为交给外部，并由 `process()` 在合适的时候调用。**

因此：

```text
嵌套函数：
process
 └── hello

回调：
hello ──┐
        ↓
      process
        ↑
        │
world ──┘
```

---

# 5. `callback` 是什么？

例如：

```cpp
void process(std::function<void()> callback)
```

这里的 `callback`：

- 不是 C++ 关键字
- 不是特殊语法
- 只是一个**变量名**

完全可以改成：

```cpp
void process(std::function<void()> f)
```

或者：

```cpp
void process(std::function<void()> handler)
```

甚至：

```cpp
void process(std::function<void()> abc)
```

都可以。

之所以经常叫 `callback`，只是因为它表达了这个变量的用途：

> 这个变量保存的是一个回调。

---

# 6. `std::function` 是什么？

C++ 中：

```cpp
std::function<void()>
```

是标准库提供的一种类型。

需要：

```cpp
#include <functional>
```

初学时可以把它理解成：

> **一个用于保存/包装可调用对象的通用类型。**

它可以包装符合要求的：

- 普通函数
- Lambda
- 函数对象
- 其他可调用对象

例如：

```cpp
void hello() {
    std::cout << "Hello";
}

std::function<void()> f = hello;

f();
```

可以理解成：

```text
f
│
└── 保存了 hello 这个可调用对象

f()
│
└── 调用 hello()
```

---

# 7. `void()` 是什么？

这是理解 `std::function` 的关键。

```cpp
std::function<void()>
```

其中：

```text
void()
```

描述的是一个**函数签名**。

它表示：

```text
参数：无
返回值：void
```

所以：

```cpp
std::function<void()>
```

可以理解成：

> 可以保存“无参数、无返回值”的可调用对象。

---

## 7.1 有参数的情况

例如：

```cpp
void hello(std::string name) {
    std::cout << name;
}
```

它的签名可以理解为：

```text
void(std::string)
```

因此：

```cpp
std::function<void(std::string)> f = hello;
```

调用：

```cpp
f("小明");
```

---

## 7.2 有返回值的情况

例如：

```cpp
int add(int a, int b) {
    return a + b;
}
```

它的签名可以理解为：

```text
int(int, int)
```

因此：

```cpp
std::function<int(int, int)> f = add;

int result = f(1, 2);
```

可以建立一个简单规律：

```text
std::function<返回值类型(参数类型...)>
```

例如：

std::function<void()>
→ 无参数，返回 void

std::function<void(int)>
→ 接收一个 int，返回 void

std::function<int(int, int)>
→ 接收两个 int，返回 int

std::function<std::string(int)>
→ 接收一个 int，返回 string

---

# 8. C++ 中不一定非要使用 `std::function`

这是一个非常重要的认识。

C++ 很早就可以实现回调，并不是因为有了 `std::function` 才有回调。

例如可以使用函数指针：

```cpp
void process(void (*callback)()) {
    callback();
}
```

也可以使用模板：

```cpp
template<typename F>
void process(F callback) {
    callback();
}
```

因此：

```text
回调
 │
 ├── 函数指针
 ├── Lambda
 ├── 函数对象
 ├── 模板
 └── std::function
```

`std::function` 只是其中一种统一抽象方式。

---

# 9. 为什么不同语言写法不同？

回调是跨语言的编程思想，不是 C++ 专属语法。

## Python

```python
def hello():
    print("hello")

def process(callback):
    callback()

process(hello)
```

Python 中函数可以作为对象/值进行传递。

---

## JavaScript

```javascript
function hello() {
    console.log("hello");
}

function process(callback) {
    callback();
}

process(hello);
```

JavaScript 中函数也可以作为值传递。

---

## C++

可以使用：

```cpp
void process(std::function<void()> callback) {
    callback();
}
```

调用：

```cpp
process(hello);
```

也可以使用其他机制。

---

## Java

Java 常通过函数式接口和 Lambda 表达类似思想，例如：

```java
Runnable callback = () -> {
    System.out.println("hello");
};
```

# 10. `callback` 在不同语言中通常也不是关键字

例如：

```python
def process(callback):
```

这里 `callback` 不是 Python 关键字。

可以改成：

```python
def process(f):
    f()
```

JavaScript 同样：

```javascript
function process(callback) {
    callback();
}
```

`callback` 也不是关键字。

因此：

```text
callback
↓
通常只是程序员约定俗成的变量名
```

真正的关键字例如：

```text
C++：void
Python：def
JavaScript：function
```

---

# 11. “函数可以被变量接收”是怎么回事？

这是理解回调的核心。

Python：

```python
def hello():
    print("hello")

f = hello
f()
```

可以理解为：

```text
hello
 ↓
函数对象
 ↓
f
 ↓
f()
```

JavaScript 也有类似机制。

C++ 同样支持把函数相关的东西交给变量保存，只不过 C++ 对不同类型的可调用对象区分得更加严格。

因此不要简单理解成：

> “C++ 不能把函数放进变量。”

更准确的是：

> **C++ 可以保存和传递函数/可调用对象，但其类型体系更加严格。**

---

# 12. 为什么 C++ 看起来比 Python/JavaScript 复杂？

核心差异之一是**类型系统**。

Python 等动态类型语言通常把更多类型判断放到运行时。

例如：

```python
f = hello
```

变量 `f` 可以在运行时指向不同对象。

而 C++ 是静态类型语言：

```cpp
int x = 10;
```

编译器在编译阶段就知道：

```text
x → int
```

因此 C++ 对“这个东西能不能这样调用”“参数和返回值是否匹配”等问题，会进行更严格的类型检查。

---

# 13. 但不能简单理解成“动态类型语言更高级”

这是一个容易产生的误区。

动态类型：

```text
更多灵活性
更多运行时检查
```

静态类型：

```text
更多编译期检查
更明确的类型信息
更多底层控制
```

它们是不同的设计取舍。

因此：

> **不是 Python 能传函数，而 C++ 不能传函数。**

而是：

> **不同语言对“函数作为值”和“可调用对象”的类型体系采用了不同设计。**

---

# 14. C++ 的 Callable（可调用对象）

C++ 中有一个很重要的概念：

> **Callable（可调用对象）**

简单来说，只要一个东西能够使用：

```cpp
thing();
```

这种形式被调用，就可以从概念上把它看成一个可调用对象。

常见形式包括：

```text
普通函数
Lambda
函数对象
函数指针
std::function
某些成员函数绑定后的对象
```

它们具体类型可能不同，但都可以表达：

> “这里有一个未来可以执行的行为。”

---

# 15. 回调真正的抽象

不要把回调死记成：

> “传一个函数。”

更准确的理解是：

> **把一个未来要执行的行为交给另一个组件，由另一个组件决定何时执行。**

所以：

```text
回调
│
├── 不等于 callback 这个单词
├── 不等于 std::function
├── 不等于函数指针
└── 不等于某种固定语法
```

这些只是实现回调的不同工具。

```text

├── 为什么？
│   ├── 解耦

│
├── callback 是什么？
│   └── 通常只是变量名，不是关键字
│
├── C++ 怎么实现？
│   ├── 函数指针
│   ├── Lambda
│   ├── 函数对象
│   ├── 模板
│   └── std::function
│
├── std::function 是什么？
│   └── C++ 标准库提供的可调用对象包装类型
│
├── void() 是什么？
│   └── 函数签名：无参数、返回 void
│
└── 跨语言
    ├── Python：函数对象
    ├── JavaScript：函数值
    ├── Java：函数式接口/Lambda
    └── C++：多种 Callable 机制
```

---

# 17. 当前阶段最重要的 5 句话

1. **回调是一种编程思想，不是某个关键字。**

2. **callback 通常只是变量名，可以改成 `f`、`handler` 等任何合法名字。**

3. **回调的核心是把“未来要执行的行为”交给外部决定，从而实现解耦。**

4. **`std::function` 是 C++ 标准库中的一种类型，用来统一包装可调用对象。**

5. **`std::function<void()>` 中的 `void()` 是函数签名，表示“无参数、返回 void”。**
